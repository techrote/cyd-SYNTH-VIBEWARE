# XENOBIO M4R — durable Windows emergency drain [Draft/HOLD]

QA batch009 (PR #20 comment 7238106373) independently reproduced the lost driver reset when a panic arrives after the outer-loop pending check but is acknowledged by render. This scoped repair exposes the durable request generation and adds an audio-backend-owned EmergencyDrain that records a generation only after successful reset. Windows services it even with all headers queued and after each render before submission; if a reset was required after render, discard that potentially stale block and retry the outer loop. Reset failure terminates the audio loop (cleanup still attempts reset). A request arriving between the final check and write is serviced on the next check; no claim of instantaneous or measured physical mute, actual waveOut driver behavior, or hard deadline. Existing coalescing and release/ack/fresh down policy are unchanged. No target HAL changes; target DMA drain is a separate physical qualification concern.
