# XENOBIO M2 Windows candidate — Draft/HOLD

The instrument starts muted. Select one of six scenes in the top strip to start the ecology. Select FEED to add food, ATTRACT to move organisms toward the gesture, DISTURB to drain food and repel, then hold/drag on the grid. Species are orange, cyan and magenta; size is energy and green intensity is food. RESET reseeds the current scene; PANIC, Escape, capture loss or dragging outside the window silence the digital engine. Lift and make a fresh scene/reset contact to restart. Actual physical or driver-level mute latency is not qualified. Windows mouse is simulated single touch, not pressure or multitouch.

Native Windows route: GDI presents the labeled actual-core RGB565 snapshot, waveOut streams 24 kHz mono with four 128-sample buffers. A separate audio worker owns the runtime render; driver calls are outside it. The emergency check attempts to discard queued driver buffers when observed, but cannot retroactively cancel audio already delivered; no physical audio latency claim. Audio device open failure is visible in title. No network or installation dependency beyond Windows system libraries.

CMake Release native GCC build in a path containing spaces executed both core and runtime tests (2/2 PASS). A local portable replay of the planned Windows smoke contact schedule produced sound, panic silence and reset sound; this is not Windows GUI execution.
