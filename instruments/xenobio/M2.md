# XENOBIO M2 — instrument-local runtime boundary [Draft/HOLD]

M1 core and media remain unchanged. The new Runtime starts muted, uses one input producer and one audio consumer, a 32-entry ordered SPSC queue, separate emergency request/acknowledgement, and a single-writer/single-reader triple-buffered value snapshot. Overflow (including release), drag into panic, out-of-bounds contact and cancel fail closed. Release plus consumer acknowledgement and a new deliberate scene/reset contact are required to restart. A blocked down is not automatically retried. The host or target adapter must provide the physical contact lifecycle, including loss/cancel; moves cannot synthesize a new down. The M1 four-tick lease remains. The block consumes at most 32 events; panic arriving during PCM generation is handled at the next block boundary, not retroactively in driver buffers. No physical mute latency is claimed. Render one frame from one returned Engine copy. No locks or allocation in Runtime::render, which remains separate from hardware I/O; intended 128-sample blocks.

The original renderer is preserved; labeled_row adds clipped 2x bitmap labels to header/footer only. BAL = balanced, DIST = disturbed, RECV = recovery. Actual ecological field pixels are unchanged. Select a scene to begin; feed/attract/disturb then touch or drag in the field. Reset reseeds, panic stops.
