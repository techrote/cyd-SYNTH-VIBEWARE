## Concrete findings and limits

- XENOBIO audioTask renders and submits 128 stereo-slot pairs; emergency generation is not serviced by the target backend, unlike its Windows backend. Even when the core acknowledges emergency and emits all-zero PCM, no driver disconnect/drain is requested. Model retains 226–249 non-midpoint samples from four consecutive actual musical blocks after replacing any one descriptor with midpoint. This is a ring-state counterexample, NOT measured residual playback or latency.
- Ecophon silenceDriver disconnects DAC then stops/clears/restarts I2S, an improvement in intended emergency semantics. However, i2s_zero_dma_buffer clears to byte zero, not DAC midpoint 0x80; upstream driver also clears completed TX buffers to byte zero with tx_desc_auto_clear (lines 458–486). Re-enabling the DAC after one successful write does not prove other descriptors are safe. Model of zeroed four-slot ring and one actual resumed PCM write retains 384 zero DAC codes, outside conservative encoded range 64–191. The model does not assert the actual descriptor order or analog voltage. A successful write alone cannot establish complete priming.
- Ecophon stops on partial write, which is appropriate. Its input.fault early continue can transiently spin without yielding if repeatedly asserted; instrument task should bound this path and maintain fault-disconnected state. XENOBIO driver fault sets sticky flag but retries writes without explicit DAC disable; coordinate fail-closed stop path rather than assuming zero PCM is analog silence.
- Do not substitute a fixed number of successful writes, timeout, or TX_DONE count for proven DMA ownership. IDF read-only source i2s_tx_reset resets current pointer and write offset, i2s_start restarts descriptor 0; write consumes queue pointers (lines 577+, 1779+, 2123+), no distinct descriptor identity is established by returned byte count. Public driver may require different backend strategy. Candidate PrimingWitness is deliberately NOT integrated with legacy I2S: requires exclusive verified per-slot full midpoint writes and timely invalidation before any enable. Test duplicate writes, partial writes, stale generations, auto-clear invalidation, faults; no physical timing claim. A real backend must also handle asynchronous faults after enabling.
